# ZzzRise — Personal Sleep Tracker

ZzzRise is a personal sleep-tracking web application. Users can create an account, choose a sleep duration or an exact wake-up time, configure a browser alarm, and review sleep history and simple progress charts.

## User features

- Create an account and log in. Each account can only access its own sleep sessions.
- The default sleep duration is **8 hours**.
- Quick choices include a 1-hour nap, 3-hour rest and 8-hour sleep goal.
- Choose a custom duration from 30 minutes to 14 hours in 30-minute steps.
- Alternatively, choose an exact clock time. If the time has passed today, the next occurrence is tomorrow.
- Select an alarm sound, adjust its volume and test it before starting.
- End a session early and save the actual duration.
- Review previous sessions, average session length, goal completion, total sleep over the last seven days and charts.
- An active session is restored after refreshing the page.

## Alarm limitation

The alarm is generated by the browser while the ZzzRise page is open and the device is awake. Press **Test sound** before starting a session so the browser can permit audio playback. Browser tabs and mobile operating systems may pause background pages, mute audio or stop a tab. The alarm is therefore **not guaranteed** if the page is closed, the device sleeps or the battery runs out. Always set a backup alarm using your phone's Clock app.

## Run locally (macOS / Linux)

Requires Python 3.10 or newer. Run these commands from the folder containing `requirements.txt`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

Generate a unique signing key and place it in `.env` as the value of `ZZZRISE_SECRET_KEY`:

```bash
python3 -c "import secrets; print(secrets.token_urlsafe(48))"
```

Then start the app:

```bash
uvicorn backend.main:app --reload
```

Open http://127.0.0.1:8000. API documentation is available at http://127.0.0.1:8000/docs during local development.

For Windows PowerShell, activate the environment with `.venv\\Scripts\\Activate.ps1`.

## Security notes

- Passwords are stored as salted PBKDF2-HMAC-SHA256 hashes, not plain text.
- Authentication uses a signed, HTTP-only, same-site cookie.
- API session queries and updates are scoped to the logged-in user's account.
- Mutating API requests with a cross-origin `Origin` header are rejected.
- The API adds browser security headers and applies a basic login-attempt throttle.
- The signing key must be unique and secret before deployment. The built-in fallback key is for local development only; production startup fails if a real key is not configured.
- Set `ENVIRONMENT=production`, `ZZZRISE_SECRET_KEY` to a generated random value, and `COOKIE_SECURE=true` when serving the app over HTTPS.
- The in-memory login throttle is suitable only for a single-process learning deployment. Use shared rate limiting (for example Redis), HTTPS, secure secret management, backups and monitoring for a public multi-worker deployment.
- The sleep history is personal data. Do not commit `zzrise.db`, `.env`, processed CSV files or the analytics warehouse to a public repository.

## Data engineering (kept behind the scenes)

The ETL pipeline is part of the project code and is intentionally not shown in the sleep-tracking interface. It is a separate batch-processing workflow:

1. **Extract:** `pipeline/extract.py` reads session records from the operational SQLite database. It does not extract names, email addresses or passwords.
2. **Transform:** `pipeline/transform.py` uses Pandas to validate timestamps, calculate actual session duration, check target achievement and create daily summaries.
3. **Load:** `pipeline/load.py` writes processed CSV files and analytics tables to `warehouse/zzrise_analytics.db`.
4. **Orchestrate:** `pipeline/run_pipeline.py` runs Extract → Transform → Load.

Run it manually for development after collecting completed sessions:

```bash
python -m pipeline.run_pipeline
```

The pipeline is batch processing: it processes stored session records when the ETL job is run. It is not stream processing. For a multi-user production service, add per-user access controls or anonymised aggregate reporting before making warehouse outputs available to analysts.
